## Intent

design/ideas-inbox.md's 'use Jaina as the content backbone' directive (2026-07-28) asked structured game content to become schema-backed Jaina records; cards, characters, races, star-atlas worlds, lore eras, Fount cosmology, and world.md's free-form narrative prose all now have their own dry-run sync tool. design/characters/web.md is the one character file every existing tool explicitly excludes (lib/parse-character-markdown.js's EXCLUDED_FILES = new Set(['web.md'])) because its '## Name — Title' character-record parser can't make sense of web.md's '## Overview' / '## <Thread Name>' heading shape — so its Overview paragraph and all 9 thread narratives (with their own participant rosters) have never reached Jaina in any form, even though each character's own 'threads' field already references these thread names as bare strings. Add lib/parse-character-web-markdown.js exporting parseCharacterWebMarkdown(markdown) and loadCharacterWebSections(), following lib/parse-world-narrative-markdown.js's shape: use lib/markdown-sections.js's splitIntoH2Sections (imported by reference, not reimplemented) to get every H2 section in design/characters/web.md, in document order. For each section, split its lines at the '**Characters:**' marker line: everything before it becomes the record's body via lib/markdown-sections.js's extractParagraph; everything after it (bulleted lines matching '- **<Name>** ...') becomes the record's characters array of bare names, in bullet order, with an empty array for sections with no such marker (i.e. Overview). Use lib/parse-card-markdown.js's slugify for each record's slug, imported by reference. Return one record per H2 section — do not hardcode the 9 thread titles; parse whatever H2 sections exist so a future 10th thread needs no follow-up unit. Add tools/sync-character-web-threads-to-jaina.js mirroring tools/sync-world-narrative-to-jaina.js's structure precisely: import loadCharacterWebSections, define buildRecord(section) returning { title, slug, body, characters }, define a NOT_IMPLEMENTED_MESSAGE naming 'Character Web Threads', and call lib/run-jaina-dryrun-cli.js's runDryRunSyncCli({ loadItems, buildRecord, notImplementedMessage, argv: process.argv }). Add one new bullet to design/DESIGN-READINESS.md Section 5's tooling list, matching the existing bullet format/placement (immediately after the tools/sync-world-narrative-to-jaina.js bullet), and extend Section 6 Gap 3's closing sentence to also name design/characters/web.md's thread narratives as now covered, citing the new tool by filename. Touch no other line of DESIGN-READINESS.md. Do not touch design/characters/web.md itself, lib/parse-character-markdown.js (including its EXCLUDED_FILES set — web.md stays excluded from the character-record parser; this is a separate, additional parser, not a change to that one), lib/markdown-sections.js, lib/parse-world-narrative-markdown.js, lib/run-jaina-dryrun-cli.js, lib/parse-card-markdown.js, or any existing tools/sync-*-to-jaina.js file or its test. Add two new, independent test files: test/parse-character-web-markdown.test.js (mirroring test/parse-world-narrative-markdown.test.js's shape: record count/order/shape, body text matching an independently-derived expectation, characters array matching the bolded bullet names, slug-matches-slugify) and test/sync-character-web-threads-to-jaina.test.js (mirroring test/sync-world-narrative-to-jaina.test.js's shape: dry-run JSON-per-line output, exact-4-fields-per-record, no-flag exits 1 with a 'not yet implemented'/'Character Web Threads'/'--dry-run' message, no network/subprocess/jaina-client usage, no JAINA_API_KEY needed, deterministic repeat output).
